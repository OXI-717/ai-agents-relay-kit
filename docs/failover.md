# Failover-цепочки в подписках (AUTO AM / AUTO KZ)

## Зачем

Релейные цепочки — единая точка отказа на уровне входа: если датацентр RELAY1 лежит
(инцидент 8.10.2026, лежал больше суток), клиент, подключённый к `RELAY1 → EXIT`,
теряет сеть целиком, хотя RELAY2 и прямой EXIT живы. AUTO-конфиг решает это: один
«сервер» в подписке, внутри которого xray сам пробует пути строго по приоритету.

Приоритет: **релеи в порядке servers.yaml, прямой выход последним**.
Приоритет: `RELAY1 → EXIT`, затем `RELAY2 → EXIT`, затем прямой `EXIT` (релеи в порядке servers.yaml).

## Как устроено (internal/build/failover.go)

Xray не имеет приоритетной стратегии балансера — запросы отклонены мейнтейнерами
(XTLS/Xray-core#3114, #5125, #5188: «considered and declined»). Используется
официальный воркараунд из #3114:

```
трафик → balancer fo-1 [proxy-1=yc] ──ok──► am
              │ все хопы мертвы
              ▼ fallbackTag: loop-2 (loopback outbound, inboundTag ilb-2)
        routing rule [ilb-2] → balancer fo-2 [proxy-2=cr] ──ok──► am
              │ снова мертво
              ▼ fallbackTag: loop-3 → [ilb-3] → fo-3 [proxy-3=am]
              │ и здесь мертво
              ▼ fallbackTag: block          ← fail-closed, не direct
```

- `burstObservatory` (subjectSelector `proxy-`, интервал 30с, timeout 5s,
  sampling 2) проверяет здоровье каждого хопа; первая проверка выполняется
  сразу на старте — фолбэк сходится за ~15 секунд (проверено офлайн и вживую).
- Полная смерть всех хопов → `block`: никакого трафика мимо туннеля.
- Каждый хоп — обычный VLESS+XHTTP+Reality outbound с `dialerProxy: fragment`.

### Правило DNS (критично!)

Первым правилом routing добавляется `ip: [адреса dns.servers] → direct`.

Без него в TUN-режиме INCY системный DNS идёт пакетами на адреса резолверов
через routing, ловится catch-all-ом и уходит в балансер: при мёртвом первом
хопе DNS умирает целиком → `DNS_PROBE_FINISHED_BAD_CONFIG` и полный блэкаут
при живых остальных хопах (инцидент 8.10). INCY обещает такой же патч для
конфигов с observatory (docs.incy.cc/en/full-xray-config, «DNS Direct
Routing»), но полагаться на него нельзя — правило детерминировано нашим
генератором. Попутно direct выводит из балансера апстрим-запросы DNS-модуля
и проб observatory.

## Формат подписки

- **INCY** (`?f=incy`): JSON-массив полных xray-конфигов
  (docs.incy.cc/en/full-xray-config) — failover-цепочки первыми, затем по
  одному конфигу на пару, затем external. Routing-профиль идёт **заголовком
  воркера** `routing` (в JSON-теле строка `incy://routing` невозможна; заголовки
  имеют приоритет над телом).
- **Happ** (`?f=happ`): как и раньше массив полных конфигов, failover-конфиги
  добавлены первыми элементами.
- Полные конфиги INCY патчит сам: socks на 127.0.0.1:10808, `stats: {}` для
  observatory, direct-правила для DNS-серверов. `dns.servers` заданы — DNS
  клиента не подменяется.

## Доставка и деплой

```sh
./bin/vpn validate && ./bin/vpn deploy subs   # KV: sub:<sha(token)>:<fmt> (+ :routing)
cd worker && pnpm exec wrangler deploy        # воркер (sub.<ваш-домен>)
```

Клиенты обновляются по `profile-update-interval` (12ч) или вручную. После
обновления подписки выбрать сервер `AUTO …` (выбор не мигрирует автоматически —
id серверов меняются при пересоздании списка).

**Откат**: `git revert` коммитов фичи → `go build -o bin/vpn ./cmd/vpn` →
`./bin/vpn deploy subs`. Возврат к линк-формату тела для INCY.

## Проверено

- Офлайн-харнес (SOCKS + dokodemo-DNS-сим, ядра 26.3.27 и 26.7.28): TCP-фолбэк
  RELAY1→RELAY2 сходится за ~15с при мёртвом RELAY1, DNS не зависит от балансера.
- Вживую (10.08, новая локация): INCY Desktop 3.8.2, сервер `AUTO AM` из
  подписки, выход am, DNS/пути зелёные, гард отработал reboot+переезд штатно.
- Happ-цепочки проверены golden-тестами и `xray run -test`; живой проверки
  Happ+AUTO пока не было (формат Happ-JSON существовал и раньше, AUTO в нём — новое).
- `xray run -test` валидирует все генерируемые конфиги (нужен
  `XRAY_LOCATION_ASSET` с geosite.dat, т.к. routing использует geosite).

## Известные ограничения

- Приоритет — не балансировка: пока жив первый хоп, остальные простаивают.
- `udp/41641` и DNS/53 в whitelist oxi-vpnks — осознанные компромиссы (см.
  логи oxi-vpnks), к цепочкам отношения не имеют, но сужают модель угроз.
- Смерть АВТОНОМНОГО выхода (am) не фолбэкается на другой выход: все пути
  цепочки ведут в один и тот же exit — фолбэк только по входам (релеям).
- INCY-клиенты до появления поддержки full-config в подписке увидят пустой
  список после обновления — обновить приложение.

  «полудохлом» туннеле — см. `oxi-vpnks` (TUNNEL DEAD + самолечение) и

- 9.10.2026 (новая локация с DPI): корнем «вчера работало — сегодня нет»
  оказались слои DNS INCY + зависающие ресурсы после неудачных подключений
  (utun244-константа, зомби-xray на 10808, админ-диалог SYSTEM_PROXY).
  Полный разбор, рецепты и хронологию коммитов — **`docs/incy-desktop.md`**.
  AUTO-цепочки в TUN-режиме INCY не работают (bypass одного адреса) —
  рабочий режим клиента: TUN + парные конфиги (RELAY2 → AM) или PROXY_ONLY;
  heal v2 в oxi-vpnks реинициализирует сам.
