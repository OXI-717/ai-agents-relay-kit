# Phase 5 — Эксплуатация

- Логи killswitch: `~/.local/state/vpnks/guard.log` (heartbeat раз в час,
  ротация ~512КБ). Тишина >1ч = демон мёртв.
- Детектор «route есть, трафика нет»: 3 промаха curl × 5 мин → TUNNEL DEAD
  → break-glass маршруты каналов управления → рестарт клиента (≤2/час) →
  HEAL FAILED в статусе при исчерпании.
- Смерть выхода: все пути цепочки ведут в один exit — фолбэк по входам
  (релеям), выход не меняется. При смерти выхода switching руками в клиенте.
- Обновление кода: правки через git (источник истины — репо), затем
  kickstart демона.

## Регламент инцидентов

1. Не рестартовать клиентское приложение живьём без согласия владельца
   (блэкаут 1–2 мин всего, включая канал агента).
2. Снять снапшоты ДО исправлений: логи клиента, xray-лог, маршрутную таблицу.
3. Диагностика по слоям: маршрут (default → utun?) → DNS (резолвит ли?) →
   TCP через туннель → сервер (с независимой точки).
