# AGENTS.md — операционный мануал

Ты — агент, разворачивающий личную VPN-инфраструктуру из этого кита.
Человек сказал «всё сделай» — твоя работа провести его по фазам `runbooks/`,
исполняя CLI-команды и проходя гейты проверки. Не импровизируй поверх команд:
каждая операция идемпотентна и проверяема.

## Железные правила

1. **Фазы строго по порядку** (`runbooks/01…05`). Не переходи к следующей, пока
   гейт текущей не зелёный. Гейт = команда с ожидаемым выводом, а не «наверное ок».
2. **Ни одного секрета в чат/лог/конфиг-пример**: UUID, приватные ключи, токены —
   через `vpn uuids fill` (SOPS) или защищённый ввод. Реальные IP и домены
   пользователя — только в его приватном реестре, никогда в `examples/` и docs.
3. **Клиентские конфиги проверять офлайн-харнесом** перед выдачей пользователю:
   `xray run -c <config>` с socks-инбордом + `curl --socks5-hostname`.
   `xray run -test` проверяет только синтаксис — этого недостаточно.
4. `dns.servers` в генерируемых конфигах — **DoH-по-IP** (`https://1.1.1.1/dns-query`).
   Plain-IP резолверы в TUN-режиме превращаются в forwarders перехвата и умирают
   на враждебных сетях (валидатор следит за литеральностью, DoH-URL — за форматом).
5. **Не рестартовать клиентское VPN-приложение пользователя на живой машине без
   явного согласия** — это блэкаут 1–2 минут всего трафика, включая твои
   собственные соединения.
6. **DNS-правило failover-конфигов**: `ip: [dns IP] → direct` всегда первое
   правило routing. Без него в TUN системный DNS уходит в балансер и умирает
   вместе с первым хопом (инцидент-класс, см. docs/failover.md).
7. Fail-closed: последний хоп цепочки → `block`, никогда → direct.
8. Sanitization-сканер (`scripts/scan-private.sh`) — часть CI; перед каждым
   push запускай локально. Паттерн: приватное живёт в приватном реестре
   пользователя, в репо — только TEST-NET и example.com.

## Реестр пользователя (данные вне репо)

Реестр живёт у владельца ОТДЕЛЬНО от кита (приватный каталог/репо). Путь:
- CLI: `vpn -registry <dir> …` или env `VPN_REGISTRY_DIR`
- Killswitch `refresh-entries` читает `VPN_REGISTRY_DIR/servers.yaml`
- Обновление боевого кода: `git pull` в checkout кита + kickstart демона
  (`sudo launchctl kickstart -k system/com.oxi.vpnks` для killswitch)

## Отладка

- Офлайн-харнес: `XRAY_LOCATION_ASSET=<geo-каталог> xray run -c <config>` с
  socks-инбордом; `xray run -test` — только синтаксис, НЕ рантайм.
- Симуляция TUN-DNS: dokodemo-door inbound на 127.0.0.1:1053 → 1.1.1.1:53,
  `dig @127.0.0.1 -p 1053` — DNS обязан резолвиться и до конвергенции
  observatory (правило DNS→direct).
- Знай ограничения INCY Desktop (если клиент пользователя — INCY):
  см. `docs/client-notes.md` (слои DNS, залипание, рецепты реинициализации).

## Что нельзя менять без владельца

- Модель fail-closed (последний хоп → block).
- Порядок приоритета хопов (релеи в порядке servers.yaml, прямой выход последним).
- Формат AUTO-имён серверов (`AUTO <EXIT> · <пути>`) — на него ориентируются
  runbooks и проверки.
